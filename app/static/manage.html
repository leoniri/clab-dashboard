Load an image archive

Vendor router images (IOS-XE, IOS-XR, NX-OS, cEOS, vJunos) cannot be pulled from a public registry. Upload a docker save archive (.tar, .tar.gz, .tar.xz) — for example a vrnetlab build made on another host.

Build a router image from a vendor file

Upload the router image the way the vendor ships it — an installer .iso or a .qcow2 disk — and the host turns it into a containerlab image: the ISO is installed onto a disk in a VM, then vrnetlab wraps the disk in a container. Takes about 5–10 minutes; progress shows below.

LAN settings

Router management interfaces get addresses from this pool on the host's LAN interface. Keep the pool outside your DHCP range — the dashboard checks that nothing answers on an address before handing it out, but a DHCP server does not know about it.

SSH gateway

FRR, plain Linux and other container nodes usually run no SSH server. For those, port 22 of their LAN address goes to the dashboard's built-in SSH gateway, which opens the node's CLI (vtysh, Cli, sr_cli…) — or a shell with ssh -t … shell.
